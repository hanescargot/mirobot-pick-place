## Learned

### 3D rotation matrix
- 2D와 같은 rule: **각 column = 기본 화살표를 돌린 뒤의 위치**
- 3D 기본 화살표는 3개: (1,0,0), (0,1,0), (0,0,1)
- **회전축 방향의 화살표는 움직이지 않음** → 그 row와 column은 `1, 0, 0` 형태
- 나머지 2x2 부분은 2D rotation matrix와 같음

| Function | 회전축 | + 방향 | Mirobot joint |
|---|---|---|---|
| `rot_z` | z | x → y | J1, J6 |
| `rot_x` | x | y → z | J4 |
| `rot_y` | y | z → x | J2, J3, J5 |

- 축 순서가 x → y → z → x로 순환. 그래서 `rot_y`만 sin 부호 위치가 뒤집혀 보임

### CCW vs CW
- 방향이 바뀌면 **두 column 모두 sin의 부호가 바뀜**
  - CCW: `[[cos, −sin], [sin, cos]]`
  - CW: `[[cos, sin], [−sin, cos]]`
- 두 화살표는 항상 90°를 유지하며 같이 돌기 때문에, 검산할 때는 column 하나만 확인해도 됨
- 검산 습관: "이 column(돌린 뒤의 화살표)이 data와 같은 쪽으로 가는가?"

### Right-hand rule
- 오른손 엄지 = 회전축의 + 방향, 나머지 손가락이 감기는 방향 = + 회전
- J1 (z축, 위쪽): 위에서 보면 반시계 → data(J1 +30°에서 y가 +)와 일치
- J2 (y축, robot의 왼쪽): x 오른쪽, z 위로 그린 옆모습에서는 y축이 화면 안쪽(⊗) → 시계 방향으로 보임
- **모든 joint는 같은 rule을 따름.** 시계/반시계는 보는 방향에 따라 달라 보일 뿐
- Robotics에서 가장 흔한 bug = 회전 부호 실수. Data로 확인하는 습관이 중요

### 4x4 homogeneous transformation chain
```python
T = (rot(rot_z(j1)) @ trans(29.69, 0, 127)
     @ rot(rot_y(j2)) @ trans(0, 0, 108)
     @ rot(rot_y(j3)) @ trans(0, 0, 20)
     @ rot(rot_x(j4)) @ trans(168.98, 0, 0)
     @ rot(rot_y(j5)) @ rot(rot_z(j6))
     @ trans(0, 0, -24.27))
```
- 회전(R)과 이동(p)을 하나의 4x4 matrix `[[R, p], [0, 1]]`로 표현 → 전부 matrix 곱셈 하나로 연결
- **회전 step**: 위치는 그대로, 바라보는 방향만 바뀜
- **이동 step**: 화면 기준이 아니라 **그때까지 돌아간 local frame 기준**으로 이동
- 결과 T: 오른쪽 위 3x1 = tool position, 왼쪽 위 3x3 = tool orientation
- J6는 tool 축 회전이라 position은 안 바뀌고 orientation만 바뀜

### `@` operator
- Python/numpy의 **matrix multiplication** 기호
- `A * B`: 같은 자리 숫자끼리 곱 (element-wise)
- `A @ B`: 진짜 matrix 곱셈 (row × column으로 곱해서 더하기)
- **Matrix 곱셈은 순서를 바꾸면 결과가 달라짐** (non-commutative)
  - "숙이고 앞으로 가기" ≠ "앞으로 가고 숙이기"
  - 그래서 FK chain의 순서가 robot 구조 그대로여야 함
